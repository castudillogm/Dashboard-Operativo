📋 Especificación Técnica de la API (v2.2)

Dashboard Operativo Multi-Delegación — Integración con ERP
📅 Fecha: 15/06/2026 📌 Versión: 2.2 (Soporte ADR y Operador en muelle) 👤 Proyecto: Dashboard Almacén

1. Resumen de la Integración

El Dashboard Operativo es un sistema multi-delegación. La delegación activa se configura mediante un PIN de seguridad en la pantalla (código por defecto 2026) y se pasa como parámetro a la API del ERP. De esta manera, el dashboard muestra únicamente los muelles y expediciones físicamente presentes en la delegación seleccionada.

✨ Novedades añadidas respecto a la especificación anterior:
  • Se ha agregado el campo operator en los muelles (docks) para mostrar el nombre del operario asignado al viaje.
  • Se ha agregado el campo booleano isADR en las expediciones (expeditions) para activar la UI especial de mercancías peligrosas (etiquetas de fondo amarillo).

🔄 Petición GET con parámetro ?delegation=BCN

2. Endpoints Requeridos

2.1. Catálogo de Delegaciones (Zonas)

Obtiene la lista completa de delegaciones logísticas configuradas en el ERP para llenar el desplegable de configuración.

PropiedadValor
Método HTTPGET
Ruta sugerida/api/v1/logistics/zones
RespuestaArray de objetos (ej. [{"code": "BCN", "name": "Barcelona"}])

2.2. Estado de Carga por Delegación

Devuelve el estado de carga actual de los muelles y las expediciones físicas en la delegación especificada.

PropiedadValor
Método HTTPGET
Ruta sugerida/api/v1/warehouse/status
Parámetro Querydelegation (Obligatorio, ej. ?delegation=BCN)
CORSDebe estar habilitado (Access-Control-Allow-Origin)

4.1. Array docks (Muelles)

Muelles activos de la delegación seleccionada.

containerIdstring"CONT-4412"Matrícula del contenedor/remolque acoplado
operatorstring"Carlos Ruiz"Nombre del operador asignado al viaje
destinationstring"PMI"Plaza de destino final asignada. Si es null o vacío, se considera en "Estado Pendiente" (sin destino designado, renderizado en gris y ocultando el badge de destino).
currentWeightnumber1250Peso cargado actualmente (en Kg)
teusnumber2Tipo de contenedor expresado en TEUS (valores válidos: 1 o 2)
targetWeightPerTeunumber10300Objetivo de peso en Kg por TEU. Este valor es dinámico y depende de la ruta específica del viaje. Para calcularlo, la API del ERP debe consultar su tabla de configuración cruzando la columna "Almacen" (ej. "BCN-ALMACEN") con la columna "Plaza Destino" (ej. "PMI" o "SCT"). 5. Casos Especiales de Lógica Logística

✈️ Caso 1: Mercancía en Tránsito (Transbordos) Si estamos en la delegación BCN y visualizamos una expedición con origin: "MAD" y destination: "PMI", el dashboard interpretará que es mercancía en tránsito.

Se visualizará en la columna de destino "PMI" y su tarjeta indicará la ruta MAD → PMI en la descripción, permitiendo identificar rápidamente que proviene de otra delegación.
🔗 Caso 2: Contenedor En Muelle (Estancia Pendiente) Cuando un contenedor físico es acoplado al muelle, el ERP crea una estancia. Si esta estancia no tiene asignado aún un viaje ni destino (destination: null y tripId: null), el dashboard muestra el muelle en la sección superior llamada "En Muelle".

El contenedor se dibuja en un tono gris neutro con borde discontinuo, se oculta la bandera de destino y el objetivo de peso se muestra como OBJ: -- kg. Una vez que en el ERP se inicia el viaje (se asigna el código de tripId y el destino destination), el contenedor se traslada automáticamente a su grupo correspondiente (Baleares/Canarias/Península/Descarga), adquiere sus colores normales y activa el semáforo de ocupación.
📥 Caso 3: Contenedor de Descarga (Entradas) Cuando la delegación recibe un contenedor lleno, el destination del muelle coincide con la delegación activa (ej. destino BCN estando en la delegación BCN).

La tarjeta se visualiza en la sección "Descarga" (posicionada a la derecha del dashboard para priorizar el flujo de trabajo). El diseño cambia para listar los expedientes internos que viajan dentro del contenedor. Cada lectura descuenta unidades pendientes; cuando una expedición llega a 0 pendientes, desaparece de la lista para reducir la carga visual. La barra de progreso es dinámica y cambia de rojo a amarillo y luego a verde, representando visualmente el porcentaje de avance de la descarga sin mostrar etiquetas de texto adicionales.
🔒 Caso 4: Cierre del Viaje y Fin de Estancia (Salida Física) El ciclo operativo del muelle cuenta con dos estados de finalización en el ERP:
  • Cierre de Viaje (status: "closed"): Al cerrarse un viaje de exportación, la tarjeta se vuelve gris y muestra el banner "VIAJE CERRADO". No se permiten más escaneos sobre ese contenedor, pero permanece acoplado al muelle. (Nota: los contenedores de descarga no muestran banner, simplemente se ocultan sus expediciones completadas).
  • Finalización de Estancia: Cuando el camión retira físicamente el contenedor del muelle, la estancia finaliza y el muelle queda libre. En el API, el contenedor desaparece del payload (containerId: null) y el dashboard dibuja el muelle vacío ("SIN CONTENEDOR") listo para un nuevo acoplamiento.

7. Alertas Visuales (Andon)

🏗️ Muelles (Ocupación de Peso)

Estancia acoplada sin viaje asignado → Gris (Pendiente)
Ocupación < 85% → Normal
Ocupación 85-94% → Alerta Peso
Ocupación ≥ 95% → Contenedor Completo

📦 Expediciones (Integridad de Partida)

pendingParts == totalParts → Sin comenzar
pendingParts < totalParts → Parcial (Pulsante)
pendingParts == 0 → Cargada (Se oculta)

8. Checklist de Integración para Sistemas

  • Implementar GET /api/v1/logistics/zones devolviendo las delegaciones disponibles en el ERP.
  • Implementar GET /api/v1/warehouse/status?delegation=[CODIGO] devolviendo muelles y expediciones físicas de dicha delegación.
  • Habilitar políticas CORS en el servidor web.
  • Asegurar que los muelles devueltos corresponden exactamente a la delegación enviada en el query param.
  • Actualizar en tiempo real el valor de pendingParts y el currentWeight del muelle al registrar escaneos.
  • Soportar los campos de estado en el muelle (status: "pending" | "active" | "closed") y la lista de expeditions internas para el flujo de descarga (importación).
